# backend

FastAPI (src layout: `src/app/`), SQLAlchemy 2.0 (async), Alembic and PostgreSQL. Packages are managed with uv.
The shared rules (the Spec Kit workflow, `docs/`, the language policy) are in the root `../CLAUDE.md`.

- Layers: router (HTTP only) → service (business rules, state transitions and the transaction; the only layer that commits) → repository (thin; SQL only). A service never raises `HTTPException`.
- Input and output schemas are separate for Create, Update and Read, and every response goes through a `response_model`. Every route sets `operation_id` explicitly, in the camelCase used in `specs/001-docs-studio/contracts/openapi.yaml`.
- Errors use one shape: `{"error": {"code", "message", "details"}}`.
- The database is PostgreSQL: Cloud SQL in production, and PostgreSQL 17 started by Docker Compose (`db`, `db-test` in the root `compose.yaml`) for local runs. The target is chosen with the `DATABASE_URL` environment variable, so Cloud SQL through the Auth Proxy also works.
- Tests live in `tests/` (outside `src`). **Tests use only a dedicated database whose name ends in `_test`**, read from `TEST_DATABASE_URL`, and refuse to run against any other database. The host must be local (`localhost` or `127.0.0.1`); the only exception is a host named explicitly in `TEST_DATABASE_EXTRA_HOSTS`, which the Compose `test` container uses for `db-test`. The name rule is never relaxed.
- Writer routes need Basic authentication, switched by the explicit setting `BASIC_AUTH_ENABLED` (required in production, where the app refuses to start without it; off by default for a local run, with a start-up warning). `BASIC_AUTH_USER` and `BASIC_AUTH_PASSWORD` come from environment variables, are never written in code, and are compared with `secrets.compare_digest`. The public API (`/api/v1/public/*`) needs none. The settings trim whitespace around the configured login (a secret saved through a console may end in a newline).
- Optional AI extra (`src/app/domains/ai/`, routes `GET /api/v1/ai/status` and `POST /api/v1/ai/draft`): off unless `AI_ENABLED` is true, and the service refuses to start if it is on without `ANTHROPIC_API_KEY`. It streams the article body as server-sent events (`delta`, then `done` or `error`; a failure before the first piece is a normal 502 `ai_unavailable`), returns a proposal only (it never touches the database), and is limited (input lengths, an output token cap, 5 requests a minute per instance, 429). The model is `ANTHROPIC_MODEL` (default `claude-sonnet-4-6`); send no prefill and no sampling parameters. The key comes from the environment (Secret Manager on Google Cloud) and is never logged. **Tests never call the API** (a fake generator is injected through `app.state`) and `tests/conftest.py` forces the AI settings off, so a developer's `.env` can never switch it on in the tests.
- `app.openapi` is wrapped in `main.py` (`_tidy_openapi`): validation errors are described with the real error envelope, the Basic scheme is declared on writer operations, and `backend/openapi.json` must be regenerated (`make check-api`) when routes change.
- The DDL is stored in `db-automation-apply/` as numbered SQL files (`001_schema.sql`). That SQL is the source of truth, and section 7 of `docs/nextjs-fastapi-architecture.html` follows it. Never edit an applied file; add a new numbered file for a change.
- Migrations: `uv run alembic upgrade head`. On Google Cloud a Cloud Run Job runs it in the manual build (`cloudbuild.yaml`); the automatic deploy from GitHub does not, so run the job by hand after a schema change (`gcloud run jobs execute docs-studio-api-migrate --region asia-northeast1`).
- `Dockerfile` and `cloudbuild.yaml` are in this folder. Docker Compose builds the `Dockerfile` for the local run (`docker compose up --build` from the repository root); Cloud Build builds it for Cloud Run (low priority).
